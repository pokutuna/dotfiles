# rm-guard: 取り返しがつかない rm を止める hook

`claude/hooks/rm-guard.sh` は、Claude Code が実行しようとする `rm` の削除対象を調べ、消しても取り返しがつくと確かめられないものを拒否する。Claude が自分で書き直すか退避できるよう、拒否の理由と次の手順を返す。人の確認を求めるのは、Claude では解決できない場合と、rm-guard が判定できない場合に限る。取り返しがつくと確かめられた `rm` には何も返さず、権限ルールと auto mode による通常の判定に任せる。

## 前提: Claude Code がコマンドの実行可否を決める仕組み

Claude Code は Bash ツールでコマンドを実行する前に、そのコマンドを次のどれかとして扱う。

- **allow**: 確認なしに実行する
- **ask**: 人に確認し、承認されたら実行する
- **deny**: 実行しない。理由は Claude に返る
- **auto mode の判断**: `defaultMode: "auto"` のとき、ルールで決まらないコマンドは AI が実行してよいかを判断する

振り分けには 2 つの仕組みがある。1 つは `settings.json` の `permissions` に書く**権限ルール**で、`Bash(rm *.ssh*)` のようにコマンド文字列のパターンで allow、ask、deny を指定する。もう 1 つは **PreToolUse hook** で、ツールの実行前に任意のスクリプトを動かし、そのスクリプトが allow、ask、deny のどれかを返すか、何も返さずに通常の判定に任せる。

両者の順序は次のとおりである。hook が先に動き、hook が deny を返せばその時点で実行しない。hook が allow や ask を返しても、権限ルールの deny と ask はその後で必ず評価される。つまり権限ルールの deny に一致するコマンドは、hook が allow を返しても実行されない。hook が何も返さなければ、権限ルールと auto mode による通常の判定に進む。

hook が返す理由 (`permissionDecisionReason`) が誰に届くかは、判定によって異なる。deny の理由は Claude に届くので、Claude はそれを読んでコマンドを直して再実行できる。ask の理由は確認画面で人にだけ表示され、Claude には届かない。

## 解こうとしている問題

`rm` を権限ルールで一律に ask にすると、一時ファイルを片付けるだけの `rm` でも毎回人の確認を待つ。長時間の作業を任せている間にこの確認で止まると、戻ってくるまで作業が進まない。一方で `rm` をすべて auto mode に任せると、消してよいかの判断が AI の解釈だけに依存し、誤って必要なファイルを消すおそれが残る。

rm-guard は、取り返しがつくと機械的に確かめられない `rm` を、auto mode の判断より前に止める。止めるときは、できるだけ Claude が自力で対処できる形で deny にし、人の確認を待つ場面を少なくする。auto mode に届くのは、消しても取り返しがつく `rm` だけになる。

rm-guard は allow を返さない。hook の allow はコマンド全体に効くので、`rm /tmp/a && curl https://example.com` の `curl` のように rm-guard が調べていない部分まで確認なしに通してしまう。何も返さなければ、コマンド全体が通常の判定に進む。auto mode 以外のモードでは、取り返しがつく `rm` もそのモードの通常の確認を受ける。

## 消してよいかの基準: 取り返しがつくか

rm-guard は、ファイルの中身や名前から重要度を推測しない。削除しても取り返しがつくかどうかだけを、ファイルシステムと git の状態から確かめる。取り返しがつくとみなすのは次の 3 種類である。

| 種類 | 取り返しがつく理由 |
| :- | :- |
| 一時ディレクトリの中 | もともと捨てる前提で置く場所である |
| 存在しないパス | 削除しても何も起きない |
| git で追跡していて、変更のないファイル | git から元に戻せる |

**一時ディレクトリ**は、システムの一時ディレクトリ (`/tmp` と `$TMPDIR`) と、git リポジトリ内の一時ディレクトリを指す。リポジトリ内の一時ディレクトリとは、リポジトリのルートより下にあり、名前が `tmp`、`temp`、`.tmp`、`.temp` のどれかに完全に一致するディレクトリである。リポジトリ内の一時ディレクトリは、`rm -rf tmp` のようにディレクトリそのものを消してもよい。システムの一時ディレクトリは中身だけが対象で、`/tmp` そのものは対象外である。ディレクトリ名だけでは中身が本当に一時ファイルかは分からないので、削除対象に git で追跡中のファイルが含まれる場合は一時ディレクトリとして扱わず、「追跡していて変更がないか」の判定に回す。テスト用の固定データを `tmp/` に置いて追跡している場合も、これで変更済みのファイルを消さずに済む。

どの判定も、シンボリックリンクを解決した後の実際のパスで行う。`tmp` という名前のリンクが `src` を指していても、実際のパスは `src` の下なので一時ディレクトリにはならない。ただし削除対象そのものがリンクの場合は、`rm` はリンク先ではなくリンク自体を消すので、親ディレクトリまでを解決する。

## 判定の流れ

`rm`、`rmdir`、`unlink` を含むコマンドは、次のように振り分ける。

```
rm を含むコマンド
 │
 ├─ 権限ルール: .ssh / .gnupg / .git を消す rm → 常に deny
 │
 └─ rm-guard
      ├─ 対象がすべて取り返しがつく                      → 何も返さない (通常の判定)
      ├─ 確かめられないが、Claude が対処できる            → deny と対処方法
      └─ Claude では対処できない、または判定できない      → ask
```

同じコマンドの中に 1 つでも確かめられない `rm` があれば、deny か ask にする。

`git rm`、`docker rm` のような別のコマンドのサブコマンドや、`git commit -m 'remove rm'` のように文字列の中に現れる `rm` は、ファイルを消す `rm` ではないので判定の対象にしない。

### deny にして Claude に対処させる場合

次の場合は deny を返し、理由と対処方法を Claude に伝える。Claude はそれを読んでコマンドを直し、人を待たずに作業を続けられる。

| 状況 | 例 | 伝える対処方法 |
| :- | :- | :- |
| 対象がグロブ、変数、コマンド置換、語頭の `=` などを含み、実際の対象を確定できない[^equals] | `rm *.log`、`rm $DIR/x` | 展開済みのパスを並べて書き直す。記号を含む名前は引用符で囲む。文字列やヒアドキュメント中の `rm` なら Write ツールで書く |
| `cd` の移動先を確定できず、相対パスの位置が分からない | `cd $X && rm a` | 絶対パスで書き直す |
| 対象の後に `-` で始まる語があり、オプションか対象か判別できない[^opts] | `rm a.txt -f` | オプションを対象より前に置き、`-` で始まる名前は `./-x` の形で書く |
| 別のコマンドを経由して `rm` を実行している | `ls \| xargs rm`、`find . -exec rm {} +`、`bash -c 'rm a'` | 対象を確かめてから、単独の `rm` で書き直す |
| 取り返しがつかないファイルで、リポジトリの中にある | 追跡していないファイル、変更のあるファイル | リポジトリ内の `.trash/` へ `mv` で退避する |
| `.trash/` の中身を消そうとしている | `rm -r .trash/20261114-153000` | 消さずに作業を続ける。`.trash/` の中身は人が消す |

取り返しがつかないファイルは、削除の代わりに退避させる。退避先はリポジトリのルートの `.trash/<日時>/` で、deny の理由には解決済みの絶対パスを埋め込んだ次のようなコマンドを、対象ごとに 1 行ずつ含める。同名のファイルが退避先で上書きし合わないよう、リポジトリのルートからの相対パスを保つ。

```sh
mkdir -p /path/to/repo/.trash/20261114-153000/docs && mv /path/to/repo/docs/notes.md /path/to/repo/.trash/20261114-153000/docs/
```

`.trash/` はグローバルの gitignore (`gitignore`) で無視するので、退避したファイルがコミットに混ざることはない。`.trash/` の中身は人が確認して消す。

### ask にして人に確認する場合

Claude が書き直しても解決しない場合と、rm-guard の簡易な読み方では判定できない場合は、ask にする。判定できない形を正しく読むために実装を複雑にするより、人の確認に倒す。

- `sudo` や `doas` を経由する `rm`。権限を上げる削除は、書き直しても安全と確かめられない
- 取り返しがつかないファイルで、git リポジトリの外にあるか、リポジトリのルートそのものか、`.git` である。`.trash/` の退避先がない。`.git` は `.trash/` へ動かすとリポジトリが壊れるので、退避を案内しない
- リダイレクトが対象とつながっている `rm`。`rm a>b` のような語は対象を読み取れない
- 引用符で囲んだ空白を含む対象。`rm "a b"` である。rm-guard は空白で語を分けるので、対象を確定できない
- rm-guard 自身が判定できない。スクリプトのエラーや、5 秒以内に判定が終わらない場合である (後述)

## 保護すべきパスは権限ルールで止める

`~/.ssh`、`~/.gnupg`、リポジトリの `.git` は、どんな状況でも消させない。これらは rm-guard ではなく、権限ルールの deny で止める。

```json
"deny": [
  "Bash(rm *.ssh*)",
  "Bash(rm *.gnupg*)",
  "Bash(rm *.git)",
  "Bash(rm *.git/*)",
  "Bash(rm *.git *)"
]
```

常に拒否するものは、状況を調べる必要がないので、文字列の一致で十分である。また、権限ルールの deny は hook が ask を返しても、何も返さなくても適用されるので、rm-guard が判定を誤ってもこれらのパスは `rm` では消えない。ただし権限ルールが止めるのは `rm` だけである。rm-guard の deny は権限ルールより先に Claude に届くので、rm-guard の側でも `.git` の退避を案内しないようにしている。

権限ルールは文字列の一致なので、`cd ~ && rm -r .s*` のようなグロブや、`rmdir`、`unlink` で書かれると一致しない。その場合も rm-guard の判定に進み、グロブは deny、取り返しがつかない対象は deny か ask になるので、確認なしに消えることはない。

## rm-guard が確実に判定できる範囲

rm-guard はシェルのコマンドを文法どおりには解析しない。`;`、`|`、`&`、括弧、改行で区切り、空白で語に分けるだけである。区切った各部分では、先頭の変数代入 (`FOO=1`) と、後続のコマンドをそのまま実行するだけのコマンド (`timeout 5`、`nohup`、`time`、`nice`、`command`、`builtin`、`noglob`)、コマンドの前に置かれる予約語 (`if`、`then`、`else`、`elif`、`do`、`while`、`until`、`!`、`{`) を外してから、`rm` かどうかを見る。予約語を外すのは、`if true; then rm a; fi` の `then rm a` のような部分を `rm` 以外のコマンドと見なすと、`rm` を見落とすからである。`rm` の引数のうち `2>/dev/null` や `> log` の形のリダイレクトは削除対象から除く。

この簡易な読み方で判定を誤るのは、止めるべきものを見落とす場合と、止めなくてよいものを止める場合の 2 種類がある。見落とした `rm` は通常の判定に進むので、rm-guard がない場合と同じ扱いになる。止めなくてよいものを止めた場合は、Claude が書き直すか人が確認すれば済む。どちらも許容し、読み方を複雑にはしない。

### cd の追跡

`cd claude && rm hooks/a.sh` のように、`cd` の後の相対パスは移動先を基準に解決する。ただし移動先を追うのは、コマンドが `&&` だけでつながっていて、括弧、パイプ、`||`、`;`、`&`、改行、`pushd`、`popd` を含まない場合に限る。たとえば `(cd /tmp && rm a); rm b` の `b` は、括弧の外なので元のディレクトリにあるが、単純に区切ると `/tmp/b` と誤って解釈してしまう。こうした形では作業ディレクトリを不明として扱い、相対パスの `rm` は deny にして絶対パスでの書き直しを求める。

ただし、コマンドの先頭が `cd` で、その直後が `&&`、`;`、改行のどれかである場合は、次に `cd`、`pushd`、`popd` が現れるまでの部分がその移動先で実行されるとみなす。`cd /path/to/repo && make; rm -r build` や、`cd /tmp && rm -rf work && mkdir work && cd work && ...` の `rm -rf work` のような形である。`;` や改行で続く場合は `cd` が失敗しても後続が実行されるが、rm-guard は移動先が存在することを確かめてから採用するので、`cd` は失敗しない。`||` で続く場合は、`cd` が失敗したときだけ後続が元のディレクトリで実行されるので、この扱いの対象外である。

この扱いは、コマンドが書かれた順に実行されることを前提にしている。ループ (`for`、`while`、`until`、`select`) があると、2 周目以降はループ内の後ろの `cd` の後で実行されるので、後ろに `cd` があるコマンドでは、ループの語が現れた位置で移動先の追跡を打ち切る。関数定義も、本体が後で `cd` の後に呼ばれうるので同様に扱う。`function` の語が現れた位置で追跡を打ち切り、`f() { rm a; }` の形の `()` を含む場合はコマンド全体の作業ディレクトリを不明とする。なお、環境変数 `CDPATH` が設定されていると相対パスの `cd` の移動先が変わるので、その場合は相対パスの `cd` を追わない。

### グロブ

グロブを含む対象は、原則として deny にして展開済みのパスでの書き直しを求める。rm-guard が自分でグロブを展開しないのは、次の 2 つの理由で実際の展開結果と一致する保証がないからである。

- Claude Code は Bash ツールのコマンドをユーザーのシェルで実行する。zsh と bash ではグロブの規則が異なり、zsh には `**` やグロブ修飾子もある
- 判定した時点と実行する時点の間にファイルが増減すると、展開結果が変わる

例外として、グロブが最後の要素だけにあり、親ディレクトリが一時ディレクトリの場合は止めない。たとえば `rm tmp/qa2/c0203L*` である。この形では、展開結果がどうなっても対象は親ディレクトリの直下に限られるので、展開しなくても安全と確かめられる。この例外は次の条件をすべて満たす場合に限る。

- 最後の要素が使うグロブ文字は `*` と `?` だけである
- 最後の要素が `.` で始まらない。`.*` が `..` に一致するシェルがあるためである
- 親ディレクトリの部分にグロブや変数を含まない。親ディレクトリは実際のパスに解決してから一時ディレクトリかを判定するので、`..` やシンボリックリンクを含んでいても判定を誤らない
- リポジトリ内の一時ディレクトリの場合、グロブに一致しうる追跡中のファイルがない。git のパス指定のグロブは `*` が `/` にも一致するので、シェルの展開より広い範囲を調べることになり、判定は厳しい側に倒れる

### 引用符とヒアドキュメント

rm-guard は、`"/tmp/a"` のように語全体を囲む引用符だけを外して読み、それ以外の引用符は特殊文字として扱う。引用符の中に区切り文字や空白があると区切り位置を誤る。割れた語には対になっていない引用符が残るので、削除対象なら特殊文字として deny か ask になる。変数やコマンド置換を含む語は、Claude が展開済みのパスに書き直せるので deny にする。

語全体が引用符で囲まれていて、中にシェルが展開するものがなければ、中身をそのまま対象の名前として判定する。単引用符なら中に `'` がないこと、二重引用符なら中に `$`、`` ` ``、`\`、`"` がないことが条件である。`rm 'app/[id]/page.tsx'` や `rm "foo.txt~"` はこれで通常の対象と同じに扱える。引用符なしの `rm app/[id]/page.tsx` はグロブとして deny にし、引用符で囲むよう伝える。

特殊文字として扱うのは、語に現れうる ASCII の記号のうち `% + , - . / : = @ _` 以外のすべてである。許す文字を決めておくことで、zsh の `^` や `<->` のようなシェルごとのグロブを個別に数え上げずに済む。

文字列やヒアドキュメントの本文も、区切られた部分として同じように読む。そのため `echo "a; rm b"` のように、文字列中に現れる「rm」に反応して止めることがある。deny の理由でその可能性を伝えるので、Claude は内容を Write ツールでファイルに書いて避けられる。

### 一覧にないコマンドを経由した rm

別のコマンドを経由する `rm` は、`xargs`、`find`、`bash -c`、`env`、`sudo` など既知のものだけを検出する。一覧にないコマンドを経由した `rm` は検出せず、何も返さずに通常の判定に任せる。一覧を広げて網羅しようとはしない。

## rm-guard が判定できないとき

rm-guard が判定できないときは、人の確認 (ask) に倒す。Claude Code は、hook が 0 と 2 以外の終了コードで終わった場合や時間切れになった場合、hook の結果を無視して通常の判定に進む[^exit2]。そのままでは、rm-guard の故障が判定なしの実行につながる。これを防ぐため、`settings.json` の hook のコマンドは、スクリプトが 0 以外で終了したら ask を出力するようにしている。

```sh
~/.claude/hooks/rm-guard.sh || printf '%s\n' '{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"rm-guard で判定できない (エラーまたは 5 秒超過) ため確認する"}}'
```

スクリプトは次の場合に 0 以外で終了する。

- `gojq` がない、入力の JSON を読めないなど、判定に必要なものがそろわない
- 判定が 5 秒以内に終わらない。対象が多い場合や巨大なリポジトリで git の状態を調べる場合に起こりうる。スクリプトは自分で 5 秒のタイマーを持ち、時間切れなら自分を終了させる

`rm` を含まないコマンドでは、スクリプトは入力の文字列を一度確かめるだけで終了し、`gojq` も起動しない。Bash ツールのすべての呼び出しで hook が動くので、この経路を軽くしておく。

## テスト

`claude/hooks/rm-guard-test.sh` は、使い捨てのリポジトリを作り、コマンドごとに期待する判定 (何も返さない、deny、ask) を確かめる。判定を変えたら実行する。

```sh
bash claude/hooks/rm-guard-test.sh
```

## 関連する設定

rm-guard の対処方法が人を待たずに働くには、次の設定が必要である。

- `.trash/` への退避に使う `mkdir` と `mv` を、権限ルールの allow にしておく (`Bash(mkdir *)`、`Bash(mv *)`)。そうしないと退避のコマンドで確認待ちになる
- グローバルの gitignore に `.trash/` を加えておく

[^equals]: zsh は語頭の `=` をコマンドのパスに展開する。`rm =python3` は `python3` の実体を消す。

[^opts]: macOS の BSD `rm` は対象の後の `-f` をファイル名として扱い、GNU `rm` はオプションとして扱う。どちらの `rm` が実行されるかは `PATH` によって変わる。

[^exit2]: 終了コード 2 は、権限ルールの評価より前にツールの実行を止める。rm-guard は終了コード 2 を使わない。
