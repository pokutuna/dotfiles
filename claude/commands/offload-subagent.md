以降のこのセッションでの作業方針を切り替える。
トークン節約のため、実装作業は Agent ツールでサブエージェントに切り出し、このメインセッションは設計・監査・レビューに専念すること。

## 方針

- タスクを分解し、独立して実行可能な実装単位に切り出す
- 各実装単位は Agent ツールで `model: sonnet` を指定してサブエージェントに実行させる。並列実行可能なものは同一メッセージ内で複数の Agent 呼び出しをまとめて発火させる
- 実装難易度が特に高い・設計判断が絡み分割できない箇所に限り、このセッション自身で直接実装してよい
- サブエージェントには、目的・背景・関連ファイルパス・完了条件を明確に伝える (曖昧な丸投げ (例:「いい感じに実装して」) をしない)
- サブエージェントの成果物は必ずこのセッションで Read して差分を確認し、設計との整合性・品質をレビューする。「意図通りに動いたか」を鵜呑みにしない
- 複雑度や設計判断を要する調査・大規模な依存関係の把握が必要な場合は `model: opus` を検討する。単純な実装・機械的な変更は `model: sonnet` で十分
- このセッション自身では、設計方針の提示、タスク分解、サブエージェントへの指示作成、成果物のレビュー・監査、最終的な整合性確認に専念する
