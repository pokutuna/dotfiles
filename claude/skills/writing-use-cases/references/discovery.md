# 全体の洗い出しと段階的詳細化

複数のユースケースをゼロから洗い出す場合は、最初から本文を書かず、粗い成果物から精度を上げる。個別の文章に入り込む前に、全体の抜けを一覧でレビューできるようにするためである。

## 手順

1. 対象と目的を1〜2文で宣言する。
2. In/Out リストで対象範囲を決める。
3. 対象と関係する主アクター、支援アクター、利害関係者を列挙する。
4. 各アクターが達成したい目的を列挙し、アクター-目的リストにする。
5. 目的を要約、ユーザー目的、サブ機能のレベルに整理する。
6. 目的の一覧をレビューして、優先度、リリース、担当を決める。
7. 選んだユースケースだけを詳細化する (SKILL.md のテンプレートと手順を使う)。
8. 個別レビューと全体レビューを行う ([checklist.md](checklist.md))。必要に応じて画面、外部インターフェイス、バッチ、データ、非機能要求との対応を整理する。

## In/Out リスト

対象になりそうなトピックを並べ、In、Out、未決定に分類する。判断が工数や責任範囲を大きく変える場合は、決裁者に判断を上げる。

| トピック | In | Out | 未決定 | 根拠・決定者 |

| 注文の確定 | ✓ |  |  |  |
| 配送会社への出荷依頼 | ✓ |  |  |  |
| 配送会社の配達管理 |  | ✓ |  |  |
| 返品時の返金 |  |  | ✓ | 業務責任者 |

## 詳細化の結果を一覧へ戻す

1本を詳細化すると、新しい外部システム、ビジネスルール、データ、手動対応、未決定事項が見つかる。それぞれを対応する一覧に追加し、ユースケース本文には詳細を埋め込まずリンクする。

```text
アクター-目的リスト
  └─ ユースケース本文
      ├─ 拡張 ── 新しい業務ルール・例外要求
      ├─ 支援アクター ── 外部インターフェイス
      ├─ データ名 ── データ定義
      └─ 利益・保証 ── テスト観点・非機能要求
```
